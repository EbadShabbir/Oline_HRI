This directory records the 14–15 September 2026 routing reliability repair. The CLI defaults to the **reliable candidate**. All four mechanisms are implemented, with bounded reply checks. The first two full release evaluations failed broader behavioral acceptance; their outcomes and measured latency remain below and in the linked reviews. Later focused repairs do not turn those failed releases into successes or establish unrestricted conversation reliability.

The candidate uses [DependencyClassifier](../../src/oline_hri/dependency_classifier.py), [LearnedSemanticRouter](../../src/oline_hri/dependency_routing.py), and [ReliableConversation](../../src/oline_hri/reliable_conversation.py). Dependency classification asks whether the requested answer needs an unstated personal fact. It does not authorize the facts that an answer may contain.

The local classifier combines the pinned 384-dimensional CPU BGE embedding with learned word 1–3-gram and character 3–5-gram TF-IDF features. A regularized ridge classifier produces four scores. Vocabulary, IDF, and weights use training examples only; separate development groups fit a rejection threshold for each predicted class from its top-two score margin. A disabled class or a margin below its threshold yields `clarify`. Scores and margins are empirical diagnostics, not probabilities or universal error bounds. Training and calibration examples are authored development material, not representative samples or independent release results. Case IDs, group names, splits, and labels never become classifier features.

The first frozen reliable candidate handled uncertain local predictions with application clarification. Its release failed because this withheld too many general answers. The revised candidate uses one bounded `qwen3:1.7b` dependency review for uncertain `none`, `optional`, or `required` predictions. A raw `clarify` prediction goes directly to a short clarification question, because a Boolean personal-facts answer cannot establish task completeness. Acceptance is also bounded below by the smallest accepted calibration margin observed for each class; the weights and exact accepted calibration set remain unchanged. Accepted required dependencies with recognizable recall intent stay in place. An accepted required prediction without that signal receives the same single bounded review, recorded as `unverified_required`; disagreement produces clarification rather than a general-answer downgrade. This addresses first-person collaborative requests that the local classifier can misread as recall, while preserving direct personal-value questions and explicit stored-input requests. The recall grammar is a bounded signal, not an intent or evidence guarantee. The review's Boolean question is whether an unstated personal value is indispensable; its input contains the current request and admitted task context, without proposed labels, scores or candidate fragments. A positive review selects `required`. For originally uncertain predictions, a negative review preserves `optional` and otherwise selects `none`. For `unverified_required`, a negative review instead selects uncertain `clarify`. Invalid, incomplete or unavailable review produces clarification. This check is fallible: identical corrected-time inputs received different verdicts across two runtime states, and the independent execution safeguard remains necessary. Independent `qwen3:0.6b` compute selection chooses a small or large generator; invalid structured size output or a recognized operational size-classification failure selects large without changing the dependency. The deployed large generator and answer reviewer are the existing `qwen3:1.7b`. The earlier Qwen semantic-routing experiment and the original `--routing-policy llm` runtime remain separate historical paths. The [development record](development_record.md) and [first release review](release_review_v1/review.md) preserve the failed release and subsequent changes.

| Mode | Intended behavior |
| --- | --- |
| `none` | Answer using the current request and general knowledge without personal-memory retrieval. A current disclosure can support a response without becoming a saved memory. |
| `optional` | Relevant authorized information may personalize an otherwise useful general answer. Empty, irrelevant, or unavailable retrieval falls back to general help. If optional evidence becomes unusable during processing, the remaining answer attempt can run without it. |
| `required` | The answer or constrained task depends on an unstated personal fact. Retrieve and verify it; when it is unavailable, ask for the missing detail. The application creates this clarification with `generation=None`. |
| `clarify` | The intended task or referent is unresolved, or a required uncertainty review cannot be validated. Ask a short clarification question. |

For mixed recall and general help, a final required dependency permits examining at most three syntactic suffix boundaries. Sentence and semicolon boundaries take priority over conjunctions, preserving the earliest whole general request. Conjunction candidates require an explicit request clause so an internal noun fragment cannot displace the full comparison or explanation. Independent local predictions must label the prefix `required` and the standalone suffix `none`, without history. This composition uses raw class predictions; their margins and uncertainty remain in the audit and do not become evidence authority. The general subrequest is copied literally from the input. If a bounded verified renderer can answer the recall portion, the application composes a personal prefix from authorized records and gives the generator only the general subrequest. The combined answer is reviewed against the full request and checked again before disclosure. Its transform is `verified_mixed_prefix`; raw model JSON remains the general answer, without fabricated model citations. If evidence is missing or cannot support a verified rendering, the application asks for the personal detail and still answers the independent general portion. Other mixed wording may require clarification.

Evidence checks run independently of the predicted mode. Personal authority comes from current asserted information and freshly authorized records linked to the request. Questions, hypothetical premises, and detected reported quotations are not converted into current assertions. Old assistant replies are never authorized sources. User facts and private facts about named contacts receive independent answer review even if routing incorrectly selected general answering. Bounded direct-recall and personal-record grammars also prevent recognized missing personal values from bypassing retrieval solely because of a general prediction. Short answers that omit the requested subject still require a witness linking that subject, its action or record, and the answer value; a fact about another person or object does not establish that link.

The proactive recall safeguard applies to a general route, while a validated optional route retains its permission to answer generally. Missing optional evidence therefore cannot be converted into a required-memory refusal by that safeguard. Independent claim checks reject recognized invented personal values when an intentionally wrong optional route reaches generation; regression tests cover specific such failures, not all possible wording.

Missing-context replies ask one short question without a memory-availability preamble. A safe general task and its application clarification now enter the same guarded task-history path as accepted general answers, so the next turn can use that context. Required recall and detected private content remain withheld. This does not turn all personal conversation history into authorized evidence.

History admission attempts to retain general tasks and explicitly requested draft artifacts. Detected personal disclosures, personal questions, and personal claims are withheld even if they were correct when first answered. A draft can retain fictional first-person wording through recognized editing followups. A detected unsafe pair in externally seeded history quarantines the whole seeded history so detached followups cannot carry old values forward. Admission is deliberately conservative and can discard useful context, including unrecognized artifact requests and some named public-topic questions. It can also miss private third-party descriptions; the independent model reviewer is an additional fallible check, not an entailment guarantee.

Retrieved snapshots are checked before use and after answer review. For final CLI output, the retriever delegates to the memory store's disclosure guard: it acquires a short write transaction, checks the exact snapshot and lifecycle authorization, and holds the lock while printing the answer. Concurrent corrections, forgetting, or pruning therefore cannot change those records between that check and the guarded write. Clock-based expiry is checked after acquiring the lock; passage of time itself cannot be locked during the final brief write. Inference, diagnostics, and interactive waits stay outside that lock.

[Reply checks](../../src/oline_hri/reply_guard.py) detect bounded repetition, copied unrelated answers, promise-only responses, unhelpful inability claims, and unsupported personal claims. An independent 1.7B [answer review](../../src/oline_hri/answer_review.py) checks usefulness, personal evidence, and deployment claims on every candidate that passes deterministic validation. It returns a verdict, not replacement factual prose. A rejected small answer can receive one 1.7B retry; there are at most two generation attempts in total. A rejected answer already using the large model normally ends in application clarification. Optional evidence reset uses the remaining bounded attempt. The historical large-to-small timeout fallback is not used by this wrapper, and an unchecked candidate is never the fallback response.

The original route remains separate from `effective_mode` and `retrieval_status`. `classifier_metadata` preserves scores, margins, thresholds, fragment checks, and artifact provenance; local classification has no invented `ChatResult`. The artifact includes training/calibration provenance, embedding identity, and a content fingerprint. Reply diagnostics preserve `attempted_models`, raw returned answer `attempts`, parsed `answer_reviews`, raw `review_attempts`, and quality issues. Returned malformed generations and review outputs remain available for audit; rejected preflight requests do not count as model dispatches. Application clarifications have no model generation, while application-composed personal prefixes have separate memory IDs from the raw generator citations.

Configured application identity, language models, the local speech-recognition roles, and terminal-text output are available as deployment facts. Detailed facts go to a generator only for relevant assistant/specification/tool requests; the independent answer reviewer always receives them. A separate bounded check rejects unsolicited instructions involving identifiers derived from the configured facts. Generic “speech” or “audio” context alone must not turn an ordinary lowercase “whisper” into a software reference. This addresses implementation-context spill, not universal correctness of tool advice. RAM, processors, physical capabilities, and other unspecified hardware are not assumed. The shared client evicts peer models before switching; reliable text sessions retain the active model and unload on exit. Voice chat unloads before each speech-recognition stage, so a retained model does not imply cross-turn voice latency savings.

Default `chat` selects the reliable candidate. These commands select it explicitly from `submodules/Oline_HRI`; use `--routing-policy llm` to reproduce the historical path:

```bash
PYTHONPATH=src .venv/bin/python -m oline_hri chat --routing-policy reliable --show-route
PYTHONPATH=src .venv/bin/python -m oline_hri chat --routing-policy reliable --voice --show-route
```

`--show-route` reports the original route and a separate `answer>` line with effective mode, retrieval outcome, actual generator or `application`, answer-attempt count, and review-attempt count. `--show-memory-ids` additionally separates retrieved, supplied, model-used, response-used, and application-used IDs. Both typed and voice chat use guarded final text output. This repair has **not recorded a new live microphone speech-to-text sample**; earlier speech smoke results do not validate this candidate.

The diagnostic runner [run_routing_reliability.py](../../scripts/run_routing_reliability.py) defaults to `--policy learned`; `--policy semantic` retains the Qwen dependency experiment, and `--policy legacy` retains Boolean routing diagnostics. Each run owns a fresh output directory and an isolated empty personal store for conversation checks. Versioned metadata records input/configuration/source hashes, including source JSON artifacts. Raw routes, model calls, answer/review attempts, and outcomes remain distinct. These defaults do not establish validation success.

It covers classifier contracts, learned routing, evidence lifecycle, optional fallback, missing recall, mixed answers, history handling, bounded retries, raw metadata, and CLI wiring. Its [validation record](../../tmp/conversation_opening_20260915/validation.json) retains all three text runs, independent reviews, final source/test hashes and both test logs. Finite English checks and model review are **not proof that every future invented fact is prevented**. Unrecognized paraphrases or disclosures, arbitrary third-party claims, entity ambiguity, and reviewer errors remain material limitations; conservative rejection can also produce unnecessary clarification. The trained classifier can confidently misclassify new wording, and empirical margin rejection can withhold otherwise answerable requests. Passing finite tests establishes the tested behaviors, not unrestricted routing accuracy or answer quality. Historical artifacts remain available for reproducibility.
