# Second targeted changing-memory repair — prospective followup protocol

This separately labeled followup follows the first 96-checkpoint repair
experiment. The root investigator reported two post-restart cm04 withholds whose
raw answers contained the supported partner but encountered another qualifier
check. That report motivates inspection and a narrow second amendment; it is
not a prospective success assumption or a new blinded review judgment. This
author has not read active partial answers or performed inference.

The first repaired run must finish, preserve all 96 checkpoints, seal its run
artifacts and complete its integrity audit before production source changes.
Its withholds, delivered answers, reviews and denominators remain immutable.
Followup observations are a new run under a new reviewed source freeze, never
retries that replace the first run and never pooled into its 96-checkpoint score.
This is development regression selected after observed failures, not held-out
validation or evidence of universal personal-memory reliability. Human
validation remains pending.

## Unchanged independent workload and expectations

Use only fictional **cm04**, the walking-partner scenario, with all three
independent correction, deletion and expiry branches. This gives **24 scored
checkpoints, three new persistent databases, three scheduled real worker process
restarts and three extra disclosure turns**. There are 10 correction, seven
deletion and seven expiry checkpoints; 15 retained-history and nine fresh-history
queries; nine matched history pairs and nine post-restart checkpoints. Tasks
require four original recalls, four replacement recalls, four historical-control
recalls and 12 unavailable-fact uncertainty responses.

The scenario object and every operation, question, checkpoint expected-state
object and rubric are copied without semantic changes from the original
pre-inference authored schedule. The independent author changes only its
top-level experiment label. It imports no production code and reads no observed
database or model answer. A JSON-value comparison must prove that all three
branch schedules and all 24 checkpoint objects match both the original baseline
and first repair exactly. No expected answer or rubric enters inference.

The separate historical-control garden tour remains an authorized dated event
before its own expiry; a venue question does not request its time. A question
asking for a forgotten former partner does not reauthorize disclosure. Current
partner queries require the latest authorized replacement, including after
restart. Missing or withheld answers never count as useful recall. Explicit
uncertainty counts as useful only when the requested fact is unavailable under
the unchanged ledger. Equivalent phrasing is accepted under the original rubric;
meaningful role/person identity, historical status and negation remain material.

## Source amendment, offline tests and preflight freeze

The anticipated narrow amendment makes a present/current request equivalent to
the supported present relationship without treating the request modifier
`current` as an additional role stored in the canonical text. It must continue
to reject a different role/person, former or previous relationship substituted
for a current one, negation, and unsupported relationship information. The final
implemented diff and tests, rather than this proposed description, must be
independently reviewed before inference.

After the first run is sealed and audited, implement the amendment, run focused
positive/negative regression tests and the relevant relationship, routing,
conversation, integration and lifecycle harness tests. Preserve unsuccessful
development attempts. Capture the final source and test hashes plus exact
commands, exit codes, counts and logs under `offline_validation_v1`. Simulated
transport answers in these tests are not followup observations.

The existing `scripts/run_changing_memory.py freeze` interface requires:

- `authored_v1/runtime.json`, `expected_ledger.json` and `protocol.md` reviewed
  before inference, with SHA256 values recorded in the review.
- `scenarios.json`, `author_ledger.py` and `authoring_v2_changes.md` in this
  followup directory, alongside the completed `offline_validation_v1` directory.
- `preflight_review_v1.json` with `approved: true`, `sha256` entries keyed by
  `runtime.json`, `expected_ledger.json` and `protocol.md`, and `source_sha256`
  exactly equal to `run_changing_memory.sources()` on the final candidate.

The reviewer must disclose any authoring role, verify the exact scope of source
changes and tests, and bind the three authored artifacts. An unreviewed source
or stale test hash cannot receive approval. No production changes occur after
this new runtime freeze. A later repair requires another labeled run.

Keep the same installed models, embedding assets, adaptive policy, seed,
generation settings and configured retention as the first run; only the reviewed
source amendment changes. Record actual model selections and answer constraints
instead of assuming nominal routes correspond to execution. The freeze captures
the new host baseline and all current source/configuration identities.

## Same real lifecycle, clock, history and process controls

Use the unchanged collector and real conversation, storage, embedding,
retrieval, generation and validation paths. Each branch starts from a new DB and
receives the same original subject and historical-control records at logical
`2026-10-01T12:00:00+00:00` through the confirmed memory API. Correction/forgetting
occur through the real APIs at +60 seconds. Each branch's mutations are isolated.
Expiry branches contain no correction or forgetting operation.

Configured retention is seven days. A record is eligible only when logical time
is strictly before `2026-10-08T12:00:00+00:00`. Test one microsecond before,
exact equality, one microsecond after and after restart at +2 seconds. The same
injected evaluation clock drives storage, retrieval and snapshot validation.
Do not change the OS clock or edit database rows to cause expiry. This is
controlled logical-time expiry, not seven days of wall-clock observation.

Preserve the actual retained conversation across each mutation. Reopen the same
database inode in a distinct worker subprocess at each restart, restoring its
serialized actual history and original snapshot to exercise stale state.
Fresh-history questions use separate empty sessions on that DB. The evaluation
restoration is explicit and does not imply deployment persists chat history.
Real lexical/semantic/hybrid probes warm the existing retrieval path. Stale
snapshots are checked through production freshness validation; no nonexistent
persistent vector cache or offline snapshot injection is claimed.

Serialize every inference call using existing leases and resource guards.
Preserve all memory acknowledgments, DB states, query/evidence/model requests,
raw and delivered answers, validators, process identities, timing and resource
records. Guard failures and interruptions stay visible; continuation may execute
only the exact untouched suffix. No attempted checkpoint is repeated or removed.

## Fresh blinded review and separate comparison

Prepare new randomized blinded packets after this collection, containing only
the question, authorized state, unchanged rubric and delivered answer. Two fresh
independent assistant reviewers score every packet without seeing first-run
answers, repair details, timing, model/route identity or system diagnostics.
Freeze their judgments before unblinding. A third blinded assistant adjudicates
any disagreement before its diagnostics are exposed. Assistant review and
pending human validation remain explicit. Previous votes cannot score new
answers.

Report all 24 planned checkpoints and classify usefulness, disclosure,
uncertainty, withholding, technical failure and missing observations separately.
Audit storage, expiry, retrieval and real restart evidence. Compare the same
24 checkpoint IDs with the first 96-checkpoint repair's cm04 subset, and
optionally the original 288-checkpoint baseline's cm04 subset, in separate
tables. Both comparisons require complete expected-state/rubric equality.
Never compare a 24-row numerator with a 96- or 288-row denominator.

Include actual generation constraints/model calls and recorded conversation
wall latency, with attempted versus delivered scope and missing timing explicit.
No model reasoning credit is inferred from constrained generation. Report the
new supported relationship delivery only if final blinded judgments support it;
safe withholding remains unsuccessful recall. Preserve every unfavorable result.

Scope is text, actual worker process restart and controlled logical expiry.
Results establish neither held-out generalization, universal dialogue handling,
OS/Ollama restart, power-loss recovery nor spoken performance.
